# 基层用药助手 Pro

面向基层医疗场景的静态药品资料管理网站，可直接部署到 GitHub Pages。

融合版草稿已升级为“基层临床助手”，并在不影响现有站点的分支中加入用药、急救、常用和我的统一入口。账号同步的最低成本核算见 [`docs/MINIMUM_COST_ACCOUNT_SYNC.md`](docs/MINIMUM_COST_ACCOUNT_SYNC.md)，非生产同步服务骨架见 [`sync-worker/`](sync-worker/README.md)。

- 从“全部药物”进入详情时复用药品 ID 索引、可见目录与双药库筛选结果，不再为一次点击重复重建整套目录；门诊详情扩展改用显式渲染事件，避免 DOM 观察器响应自身修改造成重复渲染。
- 从“药品分类”的作用、属性、剂型或自定义分类筛选进入详情时，返回键会直接回到“药品分类”，不再落入“全部药物”。
- 顶部药库切换会独立过滤首页、分类、全部药物、闪卡和缓存；搜索默认限于当前药库，也可切换为搜索全部药库。
- 支持模糊搜索、分类/剂型筛选、收藏分组、分库药品笔记、自定义药品、自定义禁忌、闪卡、JSON 导出和离线应用外壳。
- 药品列表支持左滑显示收藏、缓存或删除操作。
- 全部药物页支持多选、全选、批量修改分类和批量删除；内置药品采用可恢复隐藏，自定义药品删除前二次确认。
- 详情页支持长按/拖选说明书摘要，并保存划线、加粗或荧光笔标记；标记统一汇总到笔记本并可导出。
- 收藏支持创建分组、重命名、删除分组以及将药品移动到其他分组；删除分组时药品自动回到默认分组。
- 自定义分类支持新增、点击筛选，以及长按进入重命名/删除模式。
- 缓存管理按当前药库独立展示，支持预加载、逐项编辑本机目录字段、恢复原始字段、批量移出、批量修改分类、重复检测和 JSON 导出。
- 所有内置及自定义药品均可从详情页编辑完整目录与临床字段；内置药品修改保存为本机覆盖，可恢复原始值，修改不会自动获得说明书“已核验”状态。
- 添加自定义药品时，Cloudflare Worker 先查询 259 条可信说明书来源索引；未命中或无法解析时自动进行限定可信域名的联网检索。临床字段只从真实说明书网页原文提取，缺失内容不会猜测补写。
- 添加药物提供两种方式：输入已收录的中文商品名或通用名后点击“智能识别”（也可按回车）自动填充，或直接手动填写表单。
- 商品名通过带来源的别名表映射到通用名；命中商品名时不会套用其他厂家包装规格，规格留空并提示按药盒或现行说明书核对。
- 智能识别将药品属性 `category`（西药/中成药）与药物作用 `therapeuticClass` 分开返回和填充，不再把同一个分类值写入两个字段；所有字段都可编辑，未核验草稿无需人工放行即可保存。
- 手动录入必填药品名称、药品分类、适应症和用法用量；商品名、规格、不良反应、注意事项和备注为选填。备注同步写入本地笔记本。
- 自定义药品保存到浏览器本地存储，可选择病房或门诊药库，并自动显示在对应药库的“全部药物”和所选分类中。
- 联网导入内容始终保留来源与待复核标识，不伪装成对应厂家已核验资料；国家药监局及可信说明书链接继续用于补充核验。
- 笔记按病房药库/门诊药库独立归档，支持新增、编辑、删除和当前药库导出；详情页与笔记本中的修改会同步保存。
- 相互作用与用药禁忌页内置 12 组可追溯来源的高风险规则，优先展示禁忌联用、停药间隔和严重风险，并关联当前药库中实际存在的药物；仍可维护自定义禁忌记录。
- 自定义禁忌支持药物组合、严重程度、作用机制、可能后果和处理建议，并可搜索、筛选、编辑或删除。
- 记忆卡片支持按分类筛选、顺序或随机模式、重新洗牌和仅查看未记住药品。
- 缓存管理页支持安装 PWA、主动检查更新，以及完整导出/恢复收藏、分组、自定义药品、笔记、标记、禁忌和本机字段。
- 对明显串行错配的数据设置质控提示；未核验说明书的适应症、剂量、不良反应和注意事项显示“待核验”。
- 已接入国家药监局品种说明书范本：阿卡波糖片、莫匹罗星软膏、乳果糖口服溶液、酚麻美敏片。
- 已接入国家药监局安全修订公告：左氧氟沙星口服/注射剂、珍菊降压片；安全公告与完整说明书分开显示。

## 安全边界

本项目用于资料查询与数据整理，不替代医生诊断、处方审核、药师审方或具体厂家现行说明书。品种说明书范本也不能替代批准文号对应的现行说明书。

症状推荐与药品相互作用仍需药师结合患者情况和现行说明书审核。当前相互作用页只覆盖项目内置的 12 组高风险规则及用户手动维护的禁忌组合；“未匹配”不代表可以联用。症状推荐在后端安全服务接入前保持关闭。免费中文检索只用于资料录入辅助，不用于诊断、处方推荐或判断药物能否联用。

## GitHub Pages 发布

1. 合并本项目的 Pull Request 到 `main`。
2. 打开仓库 `Settings` → `Pages`。
3. 在 `Build and deployment` 中把来源设为 `Deploy from a branch`。
4. 选择 `main` 与 `/(root)`，点击 `Save`。
5. 等待 GitHub Actions/Pages 部署完成，再打开仓库显示的 Pages 地址。

本项目使用哈希路由（`#/home`），不需要额外配置 404 回退。

## 启用免费智能识别

Worker 使用 Cloudflare Workers 与 Browser Run 读取项目内置索引和限定可信域名检索发现的真实说明书网页，不调用 OpenAI 或 Workers AI。GitHub 仓库只需设置 `CLOUDFLARE_API_TOKEN` 和 `CLOUDFLARE_ACCOUNT_ID` 两个 Actions secrets；合并部署工作流后会自动发布。

网站已默认使用 `https://primary-medication-smart-search.tinnxq.workers.dev`；打开“缓存管理” → “免费中文检索服务”可测试连接或更换地址。完整步骤和安全说明见 [`worker/README.md`](worker/README.md)。

## 数据维护规则

- `drugs.js` 当前保存 164 条病房清单。3 个已删除品种的历史 ID 保留为空位，不再保存其名称、目录字段或临床核验资料，后续药品 ID 不前移。
- `outpatient-drugs.js` 是独立门诊目录，当前 392 条；由 `outpatient-loader.js` 在首次切换门诊药库时加载。后续导入条目必须使用唯一 ID 并包含 `pharmacyScopes: ["outpatient"]`；同一药库内不得存在完全相同的“药品名称 + 规格”组合。完全相同且需要跨库复用的品规可同时包含 `ward` 与 `outpatient`。
- 收藏和自定义禁忌跨药库共用；笔记、标记、药品列表和缓存按当前药库隔离，相互作用规则会关联当前目录中的实际药物。
- 只有带 `source.status: "verified-template"` 的临床字段可以展示为“范本已核验”。
- 每次增加说明书内容时必须记录来源 URL、核验日期，并注明是品种范本还是具体厂家说明书。
- 如果规格、通用名、厂家或剂型发生串行错配，使用 `qualityIssue` 锁定并等待包装/批准文号复核，不得靠常识补全。

## 自动质量检查
